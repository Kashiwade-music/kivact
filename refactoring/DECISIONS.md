### Read-only W2 preparation (implementation still waits for CP1)

- A-0: retain Send `MakeHandler` plus separate `ChildHooks` for embedded UI-thread construction; an Rc-owning handler cannot cross threads directly. Keep borrowed blocking handlers with `Box<dyn ShellHandler + '_>`.
- A-0: each consuming backend implementation owns session shutdown. Native guards run after handler/presenter cleanup on normal return, startup failure, and unwind; embedded guards follow actual UI-handler destruction, not the returned handle's early close request. Preserve existing deliberate leak/panic module retention. The native backend remains a lightweight factory, without capturing an entire non-Send backend into a Send UI factory.
- A-0: pre-window capabilities are supported upper bounds; the created ShellWindow's result after optional native setup is authoritative.
- A-2: services belong to each fully created ShellWindow and are constructed on its UI thread. Remove pre-window Backend/SteppedBackend services getters: without a window identity they cannot address parented dialogs or multiple embedded resize negotiations without late binding. Preserve one Services::perform entry for OS requests and UI-thread replies.
- A-2: separate RegisterFont and ReducedMotion into engine HostRequest before service forwarding. Preserve Writer-time font registration and Host-owned motion override, and synchronize the actual environment before delivering each completed effect result. E-2 treats this request separation as an A-2 prerequisite already completed.
- R-1: move the already unified types Transition unchanged. The obsolete instruction to retain as_wire is corrected; do not reintroduce a wrapper removed by V-6/18.16.
- R-1 macro boundary: keep implementation modules private and explicitly reexport the existing public union at the runtime root. macro_export already relocates constant_value there; its existing $crate::IntoValue/Prop references remain valid through those root exports. Do not expose a private implementation namespace merely to make the macro work.

### W1 definition reconciliation

- V-2: `Semantics<R>` includes the semantic properties currently split across `NodeSemantics`, both property structs, and the protocol node. The transport node retains topology/geometry plus one `semantics` value. Existing wire optional booleans take precedence; protocol-only `protected` remains a bool.
- V-2 consumer reconciliation: engine also stores `Semantics<FocusTarget>`, since existing relations may identify a draw region. The illustrative `Semantics<NodeId>` would lose that information. Map the node/region identity together to `SemanticsId` at accessibility publication.
- V-3: `EmbedOptions` is a pure value (`size`, `scale`, `prefer_gpu`, `gpu_preference`). Resize callbacks and the existing panic slot belong to shell-owned `ChildHooks`, passed explicitly beside options through embedding entry points and `Backend::open_child`. Preserve callback and panic forwarding behavior. This corrects the old options' hidden closure/state boundary rather than adding types-to-shell dependencies.
- V-3: `FailureKind` adopts existing Arvane `ErrorKind` categories Content/Resource/Backend/Surface/Unavailable; no new arbitrary classification.
- V-3 failure consolidation: Arvane's old `Error { kind, message }` has exactly the new shared failure's meaning, so remove it and reexport `Failure` directly. A newtype around `Failure` would preserve the duplication without adding a boundary contract. Rendering/text adapter errors are classified into `Failure`; core's user diagnostics retain their separate source-location/diagnostic meaning.
- V-3/E-2 fonts: W1 introduces the font-generation field without changing the existing font-registration effect/event order. After E-1 relocates the font collection owner, E-2 must advance its generation on successful registration and publish the updated environment; a later native environment refresh must not reset that generation. This follow-up is explicitly added to E-2's work order.
- V-3 layout diagnostics: keep `LayoutViolation` as a diagnostic enrichment (creation location, text, role, name, test id) around one canonical `LayoutFinding`; do not copy the rule, amount, or geometry into parallel fields. Reexport shared `LayoutRule`, `LayoutLimit`, and `LayoutCheck`, retaining the ignore-test-id builder on the shared check.
- V-4: create helper definitions alongside the other definitions, then apply the cross-module f64 conversion after those merges and before grouped consumer migration. This avoids overlapping changes to the same types without changing the wave's final scope.
- V-4 window validation: retain the existing huge-size rejection (`1e300`) after removing implicit f32 narrowing. App and resize requests share a positive/finite/u32-extent predicate in the environment vocabulary; native backends still validate the scaled physical size. Do not delete the existing invalid-size fixture merely because its value is now finite in f64.
- CP1 window regression: the existing tiny-size fixture (`f64::MIN_POSITIVE`) also relied on old narrowing to zero. Require window dimensions to be at least one logical pixel, finite, and within the unsigned native extent; App and resize share this explicit rule. Update rustdoc and retain the existing fixture. This deliberately makes the drawable-window boundary explicit instead of tying a shared f64 API to f32 underflow behavior.
- CP1 native text geometry: six catalog checks shared two false-positive 1px overflows. Measured values were 1.00000190734863281px and 1.00000333786010742px: widening Parley offset/advance separately exposed their native f32 rounding residual. In 342a2d0, establish uncut native left/right endpoints in Parley's precision, widen them, and derive the f64 width from those endpoints. Keep custom ellipsis math, glyph positions, checker tolerance, and test assertions unchanged. All six existing catalog tests pass after the fix; the temporary measurement output was removed without commit.
- CP1 rich-span decoration: paragraph decoration em lengths were formerly resolved at the paragraph font size; only an explicit span decoration used its span font size. Preserve that distinction when resolving the canonical computed style in arvane-text (fcd40ae), while keeping native font-metric fallbacks tied to the segment. This differs from inherited relative spacing between separate styled nodes, whose existing child-font resolution remains unchanged.
- CP1 direct-injection fixtures: migrate complete pointer sample constructors consistently. A Down/Up phase must carry the same button/press metadata; the two host-sync fixtures initially supplied None and are corrected in 22aa80b without changing their events or assertions. Do not loosen trace consistency checks to accommodate malformed fixtures.
- CP1 key boundaries: the old deferred-input classification included key presses but excluded the separate KeyUp variant. Matching every unified KeyInput accidentally deferred releases too, batching typed characters across the former client-turn boundary. The OTP trace exposed a real intermediate `123` versus `12a3` difference despite passing final assertions. Restrict deferral to KeyPhase::Down and keep releases pumping pending work; do not normalize away changed event batches, callbacks, writes, or commits.
- CP1 cubic endpoints: thirty bisection rounds leave residual progress 1.3969838612726965e-9 at normalized time zero for the standard curve. Its f64-scaled menu width exactly reproduced the extra LayoutChanged value 75.05000000551809. Return exact 0/1 endpoints in the private cubic solver (38641d4), preserving interior interpolation and StepsStart's intentional nonzero start. Keep exact layout comparison; do not add an epsilon or round f64 geometry back to f32 to hide work differences.
- V-4: `Generation` is a copyable opaque u64 token, starts at zero, and `next(&mut self) -> Self` checks overflow; `is_current(&self, token: Self)` compares tokens. `Sent::update` retains the appendix's `Option<&T>` contract. Detached-thread tracking remains a permanent process fact, matching all four existing sticky atomic flags.
- V-5: preserve unavailable pressure as `Option<f64>` and retain `is_primary`; the illustrative 5.4 struct omitted both distinctions. `Routed<T>` carries `input`, `target: Option<NodeId>`, `region: Option<RegionId>`, `local`, `captured`, and `activation`. A missing target preserves window-directed keyboard input. Pointer/wheel producers supply a target. Route facts are stored once. `Activation` wraps the existing adopted-activation boolean until C-4.
- V-5 IME: selection ranges are UTF-8 bytes relative to the last surrounding-text snapshot. Native conversion uses its existing snapshot to translate UTF-16 units. The engine retains the existing excerpt byte origin and adds it when applying a range to its full editor; custom sessions already supply their complete text. No redundant full-document byte offset is added to the native snapshot.
- V-6: computed text resolves inheritance while preserving relative length/current-color meanings. Keep `TextLen`, `LineHeight`, and `TextDecoration` values and resolve pixels at use; semantic absence (unlimited lines, absent caret override) may remain optional. A parent 10px font with 0.1em spacing and a child 20px font must still yield 2px spacing. Do not add a second raw-style snapshot.
- V-6 drawing: `DrawTextStyle` remains a drawing-options value because token colors and baseline anchors have meaning beyond a pure declared text style. Convert it once to canonical text-run values. Existing draw frontdoor names are retained until N-1 as the work order requires. `RgbaImage` and authored `Pixels` both reexport the canonical Arc-backed pixel type; remove their separate structs.
