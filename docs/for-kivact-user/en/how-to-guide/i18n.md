# Translate the app and set its locale

[日本語](../../jp/how-to-guide/i18n.md)

Give the app a `Locale` and a set of `Messages`. Read your own texts with
`message`, and the standard components' built-in texts ("Close", "Select all",
"Page 1 of 3") follow the same dictionary. Both can be replaced for a whole app,
for one subtree, or switched while the app runs.

Kivact carries the language and the texts. It has no translation files, plural
rules or date and number formatting of its own: you choose how to load
translations, and you pass already formatted values in.

## The shortest working translation

```rust,no_run
use kivact::i18n::{Locale, Messages};
use kivact::prelude::*;

fn app() -> impl IntoView {
    column((
        text(message("greeting", "Hello")),
        dialog("Settings", signal(true)).content(|| text("...")),
    ))
}

fn main() -> kivact::Result<()> {
    let ja = Messages::new()
        .with("greeting", "こんにちは")
        .with("dialog.close", "閉じる");

    App::new("Notes")
        .locale(Locale::new("ja-JP"))
        .messages(ja)
        .run(app)
}
```

- `Locale::new("ja-JP")` is a BCP 47 tag. Without `App::locale`, the app speaks
  the system's locale (`en-US` where the system names none) and follows it if the
  user changes it while the app runs. With `App::locale`, the app keeps your
  locale whatever the system says.
- `Messages::new().with(key, text)` is a dictionary of replacements. Keys are
  `&'static str`.
- `message(key, default)` returns a `Value<String>`: the dictionary's text for
  `key`, or `default` when it has none. Hand it straight to `text(..)`, `name(..)`
  or `placeholder(..)`. The default is what an untranslated app shows, so write
  it in your source language.
- Components draw their texts from the same dictionary, which is why
  `"dialog.close"` above renames the dialog's close button.

`message` makes a small reactive value, so call it during setup (in the component
function), not inside a handler.

## Texts with values in them

`message_with(key, default, args)` fills `{name}` placeholders. The translation
decides where each value goes, which keeps word order natural in every language.

```rust,no_run
use kivact::i18n::message_with;
use kivact::prelude::*;

fn selection(selected: Signal<Vec<u32>>) -> impl IntoView {
    // English: "3 selected". Japanese dictionary: "{count} 件選択中".
    let label = message_with("selection.count", "{count} selected", move || {
        [("count", selected.with(Vec::len).to_string())]
    });
    text(label)
}

fn main() -> kivact::Result<()> {
    App::new("Selection").run(|| selection(signal(vec![1, 2, 3])))
}
```

- The `args` closure re-runs when the values it reads change, so the text follows
  the signal.
- A `{name}` the closure gives no value for stays as written.
- Plural forms are separate keys. Choose in your code, then read the right key:
  `"items.one"` and `"items.other"` give `"{count} item"` and `"{count} items"`.
- The values are strings. Format numbers and dates yourself (with a crate of your
  choice) and pass the result in.

## Switch the language while the app runs

`provide_locale` and `provide_messages` take a signal, a memo or a closure. When
it changes, every `message` and every standard component below follows without
being rebuilt.

```rust,test_harness
use kivact::i18n::{Locale, Messages, message_with};
use kivact::prelude::*;
use kivact::i18n::{provide_locale, provide_messages};

fn page(japanese: Signal<bool>) -> impl IntoView {
    let greeting = message("greeting", "Hello");
    let items = message_with("items.count", "{count} items", || [("count", "3".to_owned())]);
    let open = signal(false);

    column((
        text(greeting),
        text(items),
        button("Open dialog").on_press(move || open.set(true)),
        button("Switch language").on_press(move || japanese.update(|j| *j = !*j)),
        dialog("Settings", open).content(|| text("...")),
    ))
    .style(style().gap(8).padding(16))
}

fn app() -> impl IntoView {
    let japanese = signal(false);
    let locale = memo(move || Locale::new(if japanese.get() { "ja-JP" } else { "en-US" }));
    let messages = memo(move || {
        if japanese.get() {
            Messages::new()
                .with("greeting", "こんにちは")
                .with("items.count", "{count} 件")
                .with("dialog.close", "閉じる")
        } else {
            Messages::new()
        }
    });

    provide_locale(locale, move || {
        provide_messages(messages, move || page(japanese))
    })
}

fn main() -> kivact::Result<()> {
    App::new("Languages").run(app)
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn switching_the_dictionary_retranslates_texts_and_components() {
        let screen = kivact::test::render(app);
        screen.get_by_text("Hello");
        screen.get_by_text("3 items");

        screen.get_by_role(Role::Button, "Open dialog").click();
        screen.get_by_role(Role::Button, "Close");
        screen.press_key(Key::Escape);
        screen.get_by_role(Role::Button, "Switch language").click();

        screen.get_by_text("こんにちは");
        screen.get_by_text("3 件");
        screen.get_by_role(Role::Button, "Open dialog").click();
        screen.get_by_role(Role::Button, "閉じる");
    }
}
```

Read the current locale with `kivact::i18n::locale()`, which returns a
`Value<Locale>`: `locale.get().language()` is `"ja"` for `ja-JP`, and
`locale.get().first_day_of_week()` is the first column of a calendar for that
region.

## Translate one part of the screen

`provide_locale` and `provide_messages` also wrap a single subtree. Siblings
keep the settings from above. A subtree's messages are laid **over** the outer
ones: a key it sets is replaced, every other key keeps the outer text.

```rust,no_run
use kivact::i18n::{Locale, Messages};
use kivact::prelude::*;
use kivact::i18n::{provide_locale, provide_messages};

fn quote() -> impl IntoView {
    column((
        text(message("quote.label", "Quote")),
        // Only this part speaks French.
        provide_locale(Locale::new("fr-FR"), || {
            provide_messages(Messages::new().with("quote.label", "Citation"), || {
                text(message("quote.label", "Quote"))
            })
        }),
    ))
}

fn main() -> kivact::Result<()> {
    App::new("Quote").run(quote)
}
```

`provide_locale` changes the locale only and `provide_messages` the texts only;
combine them when both change.

## Replace the texts of standard components

Every standard component reads its texts through `message` with a stable key,
`<component>.<purpose>`, and an English default. Setting the key in the app's
messages replaces it everywhere; setting it in a subtree replaces it there.

| Key | Default | Where |
| --- | --- | --- |
| `dialog.close` | Close | the dialog's close button |
| `toast.close` | Close | the toast's close button |
| `select.placeholder` | Select… | an empty `select` |
| `switch.on`, `switch.off` | ON, OFF | the text beside a `switch` |
| `slider.minimum`, `slider.maximum` | Minimum, Maximum | the thumbs of a `range_slider` |
| `data_table.filter`, `.empty`, `.previous`, `.next`, `.select_all` | Filter…, No results found., Previous, Next, Select all | `data_table` |
| `data_table.page`, `data_table.select_named` | Page {page} of {pages}, Select {row} | `data_table`, with values |

This is a selection, not the whole list. The rustdoc of each component names its
keys (`cargo doc -p kivact-ui --open`). A kit's own keys are prefixed with the kit
name (`basic.`, `pop.`, `game.`, `creative.`), so using two kits in one app never
makes one dictionary overwrite the other; the
[kits index](../../../for-kivact-ui-user/en/README.md) lists them per kit.

A text you do not translate keeps its English default, so a partial dictionary is
safe. To find the keys you missed, switch the language in a debug build and look
for English leftovers.

## Right-to-left text

`provide_direction` marks a subtree as right to left. Components that depend on
direction read it once during setup: a horizontal `slider` runs from the right
and its arrow keys mirror, as do the arrows of a horizontal `radio_group`.

```rust,no_run
use kivact::prelude::*;
use kivact::style::Direction;
use kivact::view::{ReadingDirection, provide_direction};

fn arabic_settings() -> impl IntoView {
    provide_direction(ReadingDirection::Rtl, || {
        column((
            slider("Volume", signal(30.0)),
            // Layout is not mirrored for you: reverse the row yourself.
            row((text("Name"), text("Ann"))).style(style().direction(Direction::RowReverse)),
        ))
        .style(style().gap(8))
    })
}

fn main() -> kivact::Result<()> {
    App::new("RTL").run(arabic_settings)
}
```

Kivact does not mirror your layout or the standard components' rows. Reverse the
rows that need it with `Direction::RowReverse`, and read
`kivact::view::use_direction().get()` once in a component of your own to decide.

## Input methods and fonts

- Input method editors (IME) work in `text_input` and `text_area` without any
  setup. Text that is still being composed is not written to the binding; only the
  confirmed text is. The locale does not change this.
- Text layout does not change with the translation: a long translation wraps like
  any other text, so check long strings in the layout. A `text_input` is a single
  line that scrolls sideways whatever the language.
- A language may need a font that is not installed on every system. Register one
  and name it in a `font_family` list; see [Images and fonts](images-and-fonts.md).
